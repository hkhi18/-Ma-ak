## 📌 Project Overview — نظرة عامة

### المشكلة

يواجه الأشخاص ذوو الإعاقة صعوبة حقيقية في اتخاذ قرار حضور الفعاليات، لأن معلومات جاهزية المكان غير معلنة: المداخل والمنحدرات، المصاعد، المواقف المهيأة، دورات المياه، ترجمة لغة الإشارة، والبيئة الحسية. فيتحوّل القرار إلى تخمين، وتتحوّل المفاجأة يوم الفعالية إلى تجربة مرهقة.

وفي المقابل، لا يملك المنظمون أداة تقيس شمولية فعالياتهم وتحدد لهم النواقص قبل النشر.

### الحل

**مَعَك** تحوّل الوصولية من وعدٍ إلى **رقم قابل للقياس**:

- **الزائر** يحدد احتياجه مرة واحدة في ملفه الشخصي، فتحسب المنصة **نسبة ملاءمة شخصية (Personal Match %)** لكل فعالية مع تفصيل لكل محور.
- **المنظم** يعبّئ **قائمة فحص الوصول**، فيحصل على **مؤشر وصولية من 100** موزّع على أربعة محاور، مع **توصيات تحسين** قبل النشر.

### المستخدمون المستهدفون

| الفئة | من هم | ماذا يريدون |
|---|---|---|
| **الزائر / المستخدم الشامل** | أشخاص ذوو إعاقة حركية أو سمعية أو بصرية أو حسية، ومن يرافقهم من الأهل | معرفة جاهزية المكان ونسبة ملاءمته لاحتياجهم قبل حجز التذكرة |
| **منظم الفعالية** | جهات حكومية، شركات تنظيم فعاليات، أفراد ينظمون معارض ومؤتمرات | الوصول لجمهور أوسع، وقياس مستوى الوصولية، والامتثال لمعايير الوصول الشامل |

### قبل وبعد (As-Is vs To-Be)

| الوضع الحالي (As-Is) | الوضع المحسّن مع مَعَك (To-Be) |
|---|---|
| الزائر يبحث يدوياً عن معلومات الوصولية | تحديد الاحتياج مرة واحدة في الملف الشخصي |
| يتصل بالمنظم أو يسأل معارفه | المنصة تحسب نسبة التوافق تلقائياً |
| إجابات ناقصة أو غير مؤكدة | عرض تفصيلي لكل محور وصولية |
| قرار مبني على التخمين | قرار واثق قبل الحجز |
| مفاجآت وعوائق يوم الفعالية | تقييم بعد الحضور يثري البيانات للجميع |

## ✨ Key Features — الوظائف الأساسية

### 1. محرك التوافق الشخصي — Personal Match Engine
يقارن احتياجات المستخدم بتجهيزات كل فعالية ويُخرج **نسبة ملاءمة** مع تفصيل لكل محور.
📁 `src/lib/accessibility-engine.ts`

### 2. مؤشر الوصولية — Accessibility Score
يحوّل خيارات قائمة الفحص إلى **درجة من 100** موزّعة على أربعة محاور مستقلة:

| المحور | Score | يشمل |
|---|---|---|
| ♿ حركي | Mobility | منحدرات، مصاعد، مواقف مهيأة، دورات مياه |
| 🦻 سمعي | Hearing | ترجمة لغة الإشارة، ترجمة فورية، سماعات مساعدة |
| 👁️ بصري | Visual | وصف صوتي، لوحات إرشادية بارزة، برايل |
| 🧠 حسي | Sensory | مناطق هادئة، مستويات ضوضاء منخفضة، تحذير الإضاءة القوية |

### 3. قائمة فحص الوصول الشامل — Accessibility Checklist
نموذج مصنّف للمنظم: مداخل، مواقف، مصاعد، دورات مياه، ترجمة، مناطق هادئة.

### 4. محرك التوصيات بالذكاء الاصطناعي — AI Recommendations
يحلل النواقص ويقترح تحسينات فورية قبل النشر مع أثرها المتوقع على الدرجة.
📁 `src/app/api/ai/suggestions/route.ts`

### 5. المساعد الذكي وتحليل الصور — AI Chat & Image Analysis
📁 `src/app/api/ai/chat/route.ts` · `src/app/api/ai/analyze-image/route.ts`

### 6. التقييمات المتخصصة بعد الحضور — Accessibility Reviews
تقييم كل محور على حدة (1–5 نجوم) بعد انتهاء الفعالية، وتنعكس النتائج في صفحة الفعالية.

### 7. تصميم شامل — Inclusive by Design
واجهة عربية بالكامل باتجاه **RTL**، متوافقة مع قارئات الشاشة، وبتباين لوني عالٍ.

## 🚀 Deployment — التشغيل والنشر

### 1. المتطلبات
- Node.js 18 أو أحدث
- حساب [Supabase](https://supabase.com)
- حساب [Netlify](https://netlify.com) للنشر

### 2. التشغيل محلياً

```bash
git clone <repository-url>
cd "code project_Nextjs"
npm install
```

### 3. متغيرات البيئة
أنشئ ملف `.env.local` في جذر مجلد المشروع:

```env
NEXT_PUBLIC_SUPABASE_URL=your-supabase-project-url
NEXT_PUBLIC_SUPABASE_ANON_KEY=your-supabase-anon-key
SUPABASE_SERVICE_ROLE_KEY=your-service-role-key
AI_API_KEY=your-ai-provider-key
```

> ⚠️ لا ترفع ملف `.env.local` إلى المستودع — أضِفه إلى `.gitignore`.

### 4. إعداد قاعدة البيانات
من لوحة Supabase → **SQL Editor**، شغّل:

```bash
supabase/schema.sql        # الجداول: profiles · events · event_accessibility · reviews
```
أو استخدم النسخة في جذر المشروع: `database_Supabase.sql`

### 5. تشغيل بيئة التطوير

```bash
npm run dev        # http://localhost:3000
npm run build      # بناء نسخة الإنتاج
npm run start      # تشغيل نسخة الإنتاج محلياً
```

### 6. النشر على Netlify

| الإعداد | القيمة |
|---|---|
| Build command | `npm run build` |
| Publish directory | `.next` |
| Node version | `18` |

الخطوات:
1. اربط المستودع بـ Netlify.
2. أضف متغيرات البيئة في **Site settings → Environment variables**.
3. فعّل النشر التلقائي من فرع `main`.

كل دفعة إلى `main` تُنتج نشراً تلقائياً للنسخة الحية:
**https://celadon-buttercream-f6b340.netlify.app**

### 7. سير العمل على GitHub
- مستودع موحّد للفريق.
- فرع مستقل لكل ميزة: `feature/<name>`.
- مراجعة عبر **Pull Requests** قبل الدمج في `main`.
- توثيق القرارات والمتطلبات داخل المستودع (`PRD` · `AGENTS.md`).

## 🧗 Challenges & Learnings — التحديات والتعلّم

| التحدي | ما فعلناه |
|---|---|
| تحويل معايير وصولية غير متجانسة إلى مؤشر رقمي عادل | وزّعنا الدرجة على **أربعة محاور مستقلة** بدل رقم واحد، فصار المؤشر عادلاً وقابلاً للتفسير |
